> ## Upgrading from 1.9.x? One manual step, once.
>
> **If you installed with the one-line installer or Homebrew, this release
> cannot install itself.** In-app updates for those installs are *new in this
> release* — 1.9.x had no way to perform them, so there is nothing on your
> machine that can fetch this. Re-run the installer once and you are done
> forever: every later update, including the next one, applies from
> **Settings → Advanced → Updates**.
>
> Your configuration, history and secrets are untouched — they live outside the
> install directory, and the previous release stays on disk.
>
> **Linux and macOS**
>
> ```bash
> curl -fsSL https://raw.githubusercontent.com/Cornerstone-Production/Stage-Utility/main/install.sh | sudo bash
> ```
>
> **Windows** — in an Administrator PowerShell
>
> ```powershell
> irm https://raw.githubusercontent.com/Cornerstone-Production/Stage-Utility/main/install.ps1 | iex
> ```
>
> **Homebrew** — on the beta track, substitute `stage-utility-beta` for
> `stage-utility` in both lines
>
> ```bash
> brew update && brew upgrade stage-utility && brew services restart stage-utility
> launchctl kickstart -k -p "gui/$(id -u)/homebrew.mxcl.stage-utility"   # macOS: brew starts it, launchd may park it
> ```
>
> **A git checkout needs none of this** — it has always self-updated, and still
> does.
>
> If you are unsure which you have, **Settings → Advanced** names it.

## Highlights

**In-app updates now work on every install method**, not just a git checkout.
A one-line-installer or Homebrew box checks for releases, applies them, and
comes back on the new version by itself. On Linux they had never worked at all —
the installer refused to run as the unprivileged service account, so the update
died before it started — and on macOS a set of launchd faults made them
unreliable: a service `brew upgrade` never restarts, a stale label, a spawn
launchd parks, and an update script running from the directory being replaced.
Each is fixed and covered by a test. A failed update now also reports *why*
instead of appearing to hang, and a crash brings the server back rather than
leaving the box dark.

**The patch sheet** is new: stage inputs and outputs, rack and snake routing,
named variants, per-week tweaks, ownership bands, CSV/XLSX import and export,
and a printable diagram. **ScriptView** runs a service script on a display.

**Recording got more honest.** Three faults that lost data silently are fixed:
a single Planning Center auth blip could stop SPL, attendance and timeline
capture for the rest of a service; the post-service attendance taper never ran
on the last service of a day; and SPL automation rules only fired while a
browser happened to be watching an SPL meter.

Also in this release: automation triggers relative to rehearsal and service
times, Companion signals from the scheduled roster, layout-editor improvements
including embedding a View inside a custom layout, an uninstaller covering
every install method, and a large reliability pass over the live event stream.
